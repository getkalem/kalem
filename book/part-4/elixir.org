The =elixir= plugin of =getkalem/plugins= makes Kalem an editor for
Elixir, EEx and HEEx. It is a [[file:language-plugins.org][language plugin]]: a manifest, syntaxes
and settings. Its own README lists the same and is kept with it.

* What is followed

- *The grammar* of the highlighter is the Sublime syntax of
  [[https://github.com/princemaple/elixir-sublime-syntax][princemaple/elixir-sublime-syntax]] (MIT), unchanged: Elixir with
  =~H= sigils highlighted as HEEx, =~L= and =~E= as EEx, Markdown in
  =@doc= and =@moduledoc=, SQL in =~SQL=; HEEx with components
  (=<.button>=, =<Module.comp>=), ={…}= attributes and =<%= … %>=
  blocks highlighted as Elixir. HEEx and EEx extend Sublime Text's
  HTML, which the plugin ships as a base only.
- *The server is the oracle* for everything else: Expert, the Elixir
  team's language server, where it is installed; ElixirLS otherwise.
  Kalem shows what the server says and changes nothing in it.

| Files                                     | Language |
|-------------------------------------------+----------|
| =.ex=, =.exs=, =mix.lock=, =.formatter.exs=, =.credo.exs=, =.iex.exs=, =#!= with =elixir=, =iex= or =mix= | Elixir |
| =.heex=, =.html.heex=                     | HEEx     |
| =.eex=, =.html.eex=, =.leex=, =.html.leex= | EEx     |

* The project

The root is the outermost folder up from the file with a =mix.exs=,
so an umbrella project is one workspace and its applications under
=apps/= are workspace folders. A file outside a Mix project is served
with its folder as the root. ElixirLS builds into =.elixir_ls/= under
the root with =MIX_ENV= =test= by default; set =mixEnv= in the plugin's
settings to change it.

* Installing a server

| Server   | How                                                                                         |
|----------+---------------------------------------------------------------------------------------------|
| Expert   | A release from [[https://github.com/elixir-lang/expert/releases][elixir-lang/expert]], with =expert= on the =PATH=          |
| ElixirLS | =brew install elixir-ls=, or a release unzipped to =~/.elixir-ls/release=                 |

=kalem lsp status FILE= says which is used and where it was found.

* Known differences

- ElixirLS 0.27 on Elixir 1.20 answers the document symbols request
  with modules only, without their functions; Kalem lists what it
  receives.
- Regular expressions in =~r= are highlighted as strings: the
  package's PCRE syntax uses subroutine calls, which the pure-Rust
  regular expressions of Kalem's highlighter (=fancy-regex=) do not
  have.
- CSS and JavaScript inside a HEEx =<style>= or =<script>= are
  highlighted with Kalem's built-in syntaxes, which are older than the
  HTML base the plugin ships.

* Not implemented

No embedded =iex=: Kalem ships no REPL (D28), and a terminal is one key
away. Running the test at the cursor (=mix test FILE:LINE=) and the
project's tests waits for the project's run and test keys (T2.7i.8);
rename, code actions and signature help wait for T3.8.2.
