Kalem opens a =.tex= file rendered, as the document reads, and edits it
in place. The file stays standard LaTeX: Kalem defines no dialect, adds
no syntax and never regenerates the file from a tree. This chapter is
the reference for what Kalem reads in a LaTeX document, what it draws,
what it leaves as source, how it edits, checks and builds, and against
what each of these is tested. It describes the code at =main=: the
crates =latex-syntax= and =latex-model= and the =latex_*= modules of
=kalem-core=. The manual's chapter [[file:../part-1/latex-files.org][LaTeX files]] says the same things
for the writer; this one says them exactly.

* The standard and the oracles

LaTeX has no reference grammar. TeX is a macro language whose category
codes, commands and environments can all be redefined, and the
structure of a document depends on the class and packages it loads.
Kalem therefore cannot claim, as its Org mode does, to agree with a
reference parser on every input. The standard it follows is
/standard LaTeX as the TeX engines accept it/: TeX's standard category
codes, the LaTeX 2ε kernel, the standard classes (=article=, =report=,
=book=), =amsmath=, and the conventions of the common packages. Its
claims are narrower and each has an oracle.

| Claim                                                                                  | Oracle                                                                                                                                                                                   | State                                                                                                                  |

=kalem diff-pandoc FILE... [--summary] [--format json]= runs
=pandoc -f latex -t json= on each file (in the file's folder) and counts

| =inline-math=    | =$…$= and =\(…\)= in each file's body                                                                                              | =InlineMath=                                    |
| =display-math=   | =$$…$$=, =\[…\]=, and =equation=, =align=, =gather=, =multline=, =eqnarray=, =alignat=, =flalign=, =displaymath= (starred too) not inside another math environment | =DisplayMath=                                   |
| =citations=      | the keys of every citation command                                                                                                 | the citations of each =Cite=                    |
| =footnotes=      | =\footnote= commands                                                                                                               | =Note=                                          |
| =figures=        | floats of kind figure (=figure=, =figure*=, =wrapfigure=)                                                                          | =Figure=                                        |
| =tables=         | =tabular=, =tabularx=, =longtable= environments                                                                                    | =Table=                                         |

| =list-items=     | =\item= commands                                                                                                                   | the items of =BulletList=, =OrderedList=, =DefinitionList= |

A file's body is its =document= environment, or the whole file for an
included file without one. Without =--summary= it prints each
disagreement as =FILE: CATEGORY: kalem A, pandoc B=; with =--summary=,
how many files agree in each category; =--format json= gives every
category of every file with an =agree= flag.

* The rules

The three rules of every standard mode ([[file:overview.org][Part II overview]]) take this
form in LaTeX:

1. *Ranges, never text.* The parser returns a tree whose leaves are
   ranges of the file. The view, the model, the diagnostics and every
   command work on those ranges. An edit replaces only the characters it
   changes; spacing, comments, line endings and the order of arguments
   stay as the author wrote them. There is no pretty printer behind any
   command; =kalem fmt= changes only blanks and says so.
2. *No extension.* Everything an editing command writes is conventional
   LaTeX that the engines compile: =\textbf{…}=, =\item=,
   =\begin{…}= … =\end{…}=, =\cite{…}=. Nothing Kalem needs is stored in
   the file; there are no magic comments of Kalem's own. The toolbar and
   menus of a LaTeX document carry only LaTeX commands.
3. *Unknown constructs stay visible.* A command or environment outside
   the rendered subset is drawn as its source: its name dimmed, its
   arguments as text with their braces. Nothing is hidden and nothing is
   guessed. A long environment the view does not render folds to its
   first line away from the cursor, as a drawer does in Org, and unfolds
   when the cursor enters it.

* Files and detection

A file is a LaTeX document when its extension is =.tex=, =.latex= or
=.ltx=, or when its first line carries an Emacs mode line naming
=latex=, =tex= or =ltx= (=% -*- mode: latex -*-=). =.sty=, =.cls= and
=.bst= files are not documents: they open as plain text. =.bib= files
open in the BibTeX grid, described in [[file:bibtex.org][BibTeX]]. =kalem check=
and =kalem fmt= treat =.tex= and =.ltx= files as LaTeX.

* Parsing

The parser is the =latex-syntax= crate. It produces a lossless rowan
tree: concatenating the tree's tokens gives back the input, byte for
byte, for any input, balanced or not. It never fails and never panics.

** Tokens

The lexer uses TeX's standard category codes, fixed:

| Characters                     | Token            | Meaning                                                                                    |
|--------------------------------+------------------+--------------------------------------------------------------------------------------------|
| =\= and letters                | =CONTROL_WORD=   | a command name: =\= and a run of ASCII letters (and =@= after =\makeatletter=)             |
| =\= and one other character    | =CONTROL_SYMBOL= | =\\=, =\%=, =\(=, =\,=, =\é=; a line ending after =\= counts as the character              |
| ={= =}=                        | =L_BRACE= =R_BRACE= | groups and mandatory arguments                                                          |
| =[= =]=                        | =L_BRACKET= =R_BRACKET= | optional arguments where a signature asks for one; text elsewhere                   |
| =$=, =$$=                      | =DOLLAR=, =DOUBLE_DOLLAR= | math shifts                                                                       |
| =&= =#= =^= =_= =~=            | one token each   | alignment tab, parameter, superscript, subscript, tie                                      |
| =%= to the end of the line     | =COMMENT=        | a comment (the line ending is not part of it)                                              |
| spaces and tabs                | =WHITESPACE=     |                                                                                            |
| one line ending                | =NEWLINE=        | LF, CRLF or a lone CR                                                                      |
| a line ending and blank lines  | =PAR_BREAK=      | a line ending followed by lines of only spaces and tabs: the end of a paragraph            |
| anything else                  | =TEXT=           | a run of characters with no special meaning                                                |

Two token kinds come from the parser rather than the lexer: =STAR= (the
star of =\section*= and of a starred environment's argument list) and
=VERBATIM= (text taken as it is), and =ENV_NAME= is the name inside
=\begin{…}= and =\end{…}=. An environment name is a run of ASCII letters,
digits and =*=, =@=, =:=, =_=, =-= between braces, with spaces or tabs
allowed between =\begin= and the brace.

** Paragraphs, groups and arguments

The document is a sequence of paragraphs separated by paragraph
breaks; so is the body of every environment that is not verbatim. A
paragraph is a sequence of elements: tokens, groups, commands,
environments and formulas. A group ={…}= closed before the end of its
container may contain paragraph breaks.

A command takes the arguments its /signature/ lists, read left to right:

| Letter | Argument          | How it is read                                                                                                                                                                                                                                                  |
|--------+-------------------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| =*=    | an optional star  | a =*= immediately after what precedes it, with no blank between                                                                                                                                                                                                 |
| =o=    | an optional argument | after spaces, tabs and at most one line ending: =[= with a matching =]= before the end of the paragraph and before an unmatched =}= (groups and verbatim arguments inside are skipped); otherwise there is no optional argument and the =[= is text          |
| =m=    | a mandatory argument | after spaces, tabs and at most one line ending: a group; or a single control word (not =\begin=, =\end=, =\verb=, =\lstinline=, =\url=, =\href=, =\makeatletter=, =\makeatother=); or a control symbol; or the first character of a text run. Anything else ends the argument list |

A command not in the signature table takes no arguments. What follows
it is parsed as ordinary text and groups, which keeps it visible: an
unknown =\foo{a}{b}= is the command =\foo= followed by two groups.

The commands whose arguments are text even inside math (=\text=,
=\textrm=, =\textbf=, =\textit=, =\textsf=, =\texttt=, =\textnormal=,
=\mbox=, =\hbox=, =\intertext=, =\emph=, =\textup=) parse their arguments
in text mode, so =$= inside them starts a formula.

** Environments

=\begin{name}= opens an environment that ends at the matching
=\end{name}=. Pairing is done in one pass before parsing, as TeX pairs
them: each =\end{x}= closes the nearest open =x=, and environments opened
inside it and not closed stay unclosed. The environment is an
=ENVIRONMENT= node holding a =BEGIN= node (the command, the name and the
arguments of its signature), a =BODY= and an =END=.

Verbatim environments keep their body as one =VERBATIM= token: the body
ends at the first literal =\end{name}= in the text, so nothing inside it
is a command, a comment or a group. Their arguments are read on the
=\begin= line only, as they are written. The verbatim environments are
=verbatim=, =verbatim*=, =Verbatim=, =Verbatim*=, =BVerbatim=,
=lstlisting=, =minted=, =comment=, =filecontents= and =filecontents*=.

The body of a math environment is parsed in math mode. The math
environments are, each with its starred form: =equation=, =align=,
=gather=, =multline=, =eqnarray=, =alignat=, =flalign=, =math=,
=displaymath=, =split=, =aligned=, =gathered=, =alignedat=, =cases=,
=dcases=, =matrix=, =pmatrix=, =bmatrix=, =Bmatrix=, =vmatrix=,
=Vmatrix=, =smallmatrix=, =array=. Every other environment's body is
parsed in text mode.

** Math

| Delimiters   | Node           | Mode in which it opens |
|--------------+----------------+------------------------|
| =$…$=        | =INLINE_MATH=  | text                   |
| =\(…\)=      | =INLINE_MATH=  | text                   |
| =$$…$$=      | =DISPLAY_MATH= | text                   |
| =\[…\]=      | =DISPLAY_MATH= | text                   |

Inside math, =$= closes inline math and =$$= closes display math;
=\(= and =\[= are not special. A formula not closed before the end of
its paragraph ends there, with a diagnostic.

** What the parser does not follow

The parser reads LaTeX's conventions, not TeX's macro expansion. It does
not follow:

- =\catcode= changes, =\ExplSyntaxOn= (where =_= and =:= are letters),
  active characters and babel's shorthands. Only =\makeatletter= and
  =\makeatother= change the lexing.
- Macros: a =\newcommand= does not give its command a signature, so the
  arguments of the document's own macros parse as the groups after an
  unknown command. Bodies of definitions are ordinary tokens (=#1= is a
  =HASH= token and the text =1=).
- Verbatim environments defined by the document or a package beyond the
  list above (=\lstnewenvironment=, fancyvrb's
  =\DefineVerbatimEnvironment=): their bodies parse as LaTeX.
- The primitive form =\input file= without braces: the =m= argument is
  the first character.
- Conditionals: =\iffalse= … =\fi= parses normally; only the view dims
  it.

** Error tolerance

Unbalanced input is closed where a reader would close it, and each
closing is reported with its range:

| Situation                               | What the parser does                                                                                                   | Message                                   |
|-----------------------------------------+------------------------------------------------------------------------------------------------------------------------+-------------------------------------------|
| ={= with no matching =}=                | the group ends at the end of the paragraph                                                                            | ={ is not closed=                         |
| =}= with no ={=                         | kept as a token                                                                                                        | =} without {=                             |
| =\begin{x}= with no =\end{x}=           | the body ends at the next sectioning command (=\part= to =\subparagraph=) after it, or at the end of its container    | =\begin{x} is not closed=                 |
| =\end{x}= with no open =x=              | an =END= node on its own                                                                                               | =\end{x} without \begin{x}=               |
| =\begin= without a name                 | an ordinary command                                                                                                    | =\begin without an environment name=      |
| a formula not closed                    | it ends at the end of the paragraph                                                                                   | =math is not closed=                      |
| =\)= or =\]= outside math               | kept as a token                                                                                                        | =\) without its opening=, =\] without its opening= |
| =\verb= or =\lstinline= without delimiter on the line | an ordinary command                                                                                         | =\verb without its closing delimiter=     |
| =\url= or =\href= without braces on the line | an ordinary command                                                                                               | =\url without its address=                |
| nesting deeper than 1,000 levels        | deeper groups, commands and formulas stay flat tokens                                                                 | =nested too deeply to be structured=      |

Parsing stays linear on unbalanced input because the pairing of braces
and environments is computed once, before the tree is built. These
messages are the diagnostics with code =latex-syntax= (see Diagnostics).

** Incremental reparsing

After an edit, =Parse::reparse= parses again only the paragraph around
the edit, and only when that is certain to give the tree a full parse
gives; otherwise it parses the whole text. The region is found by going
down into the innermost closed, non-verbatim environment whose body
holds the edit strictly inside (after the body's first non-blank token,
which must not be =[=, so the arguments of =\begin= cannot change, and
before its =\end=), then taking the children of that body from the
paragraph break before the edit to the one after it. The full parse is
taken when any of these holds:

- the edit reaches the start or the end of an environment's body, where
  no paragraph break separates it from =\begin= or =\end=;
- a diagnostic of the old parse overlaps the region, or a
  =\makeatletter= or =\makeatother= lies in it;
- the document has an environment left open and the region holds a
  sectioning command, before or after the edit;
- the region holds the =\begin= or =\end= of a verbatim environment,
  before or after the edit;
- inside an environment, without a paragraph break at its end, the
  region's last line holds =%=, =\verb=, =\url=, =\href= or =\lstinline=;
- the new region, parsed alone, has a diagnostic, an unclosed
  environment or a =\makeatletter= toggle, or does not begin and end with
  the paragraph breaks the old one had.

The property tests check that the result is always the full parse's
tree. Measured (=book/part-5/performance.org=): a 1 MB paper parses in
32 ms and a keystroke reparses in 0.64 ms (median).

* Projects

A document of several files is one project. The =latex-model= crate
finds its root document and reads the included files where they are
included, so that numbers continue across files and labels resolve
between them.

** The root document

=find_root= decides the root of a file in this order; the first that
applies wins:

1. A =% !TEX root = FILE= line among the first 20 lines (=!= optional,
   =TEX root= in any case), resolved from the file's folder, =FILE.tex=
   tried before =FILE= when the name has no =.tex= extension; it must be
   readable.
2. =\documentclass[MAIN]{subfiles}=: the subfile's main document, resolved
   the same way.
3. A file named =NAME.latexmain= in the file's folder or a folder above
   it: =NAME= in that folder.
4. A workspace setting naming the root. (The function takes one; no
   setting feeds it yet, so this step never applies.)
5. The file itself, when a line of it starts with =\documentclass= (not
   the =subfiles= class).
6. The first =.tex= file with a =\documentclass=, in the file's folder or
   a folder above, whose project includes the file.
7. The file itself.

#+begin_src latex
% !TEX root = ../thesis.tex
\chapter{Methods}
\label{ch:methods}
#+end_src

The editors look for the root on a thread when a =.tex= file opens, and
again when an edit within the first 4,096 bytes changes the =% !TEX root=
line.

| Command                 | Where the file is looked for                                                                                  | Folder for the =\input= and =\include= inside it |
|-------------------------+---------------------------------------------------------------------------------------------------------------+--------------------------------------------------|
| =\input{name}=          | the current base folder: =name.tex=, then =name= (only =name= when it ends in =.tex=)                         | the same base                                    |
| =\include{name}=        | the current base folder: =name.tex= only                                                                      | the same base                                    |
| =\subfile{name}=        | the including file's folder: =name=, then =name.tex=                                                         | the subfile's folder                             |
| =\import{dir}{name}=    | =dir= relative to the root's folder (or absolute): =name.tex=, then =name=                                    | the imported file's folder                       |

The base folder starts as the root's folder, as LaTeX runs there. Each
included file is read in place: its events are numbered where the
include stands. A file included by =\subfile= counts only inside its
=document= environment, as the subfiles package arranges; an included
file's =\documentclass= is ignored. =\includeonly{a,b}= marks the
=\include= files it leaves out as excluded, but they are still read and
numbered, because LaTeX keeps their numbers from their =.aux= files. A
file already being read (a cycle) is not read again, and reading stops
32 files deep. =\graphicspath{{a/}{b/}}= adds folders in which pictures
are looked for.

#+begin_src latex
\documentclass{report}
\usepackage{import}
\includeonly{chapters/intro}
\begin{document}
\include{chapters/intro}
\include{chapters/results}
\import{appendices/}{data}
\end{document}
#+end_src

** A file seen as part of its project

In the editors the model of a file of a project is the project's model
/seen from/ that file (=Model::seen_from=): the file becomes file 0 and
the root takes its index, so everything in it is numbered as the whole
document numbers it (a chapter file's first chapter is numbered after
the chapters before it) and its references to labels in other files
resolve. The file being edited comes from the editor, with its
incremental parse; the other files come from the disk and are read
again when their modification time changes. A root document that
includes nothing needs no project and uses its own model.

* The document model and numbering

The model (=latex_model::Model=) holds: the document class and its
options; the packages loaded, with their options, one entry per name of
=\usepackage{a,b}= or =\RequirePackage=; the preamble (everything before
=\begin{document}=, or the whole file without one) and the body; the
sectioning commands with their numbers and parents; labels with their
numbers and targets; references; citations with their notes; floats with
their captions; equations; the theorem-like environments declared and
used; footnotes; the macros defined; the environments defined; the
bibliography sources and style; the includes; =\includeonly=;
=\graphicspath=; and the project's files. It is kept per paragraph
between edits: after an edit only the changed paragraphs are read again
and numbering runs over what they say.

| -1    | =\part=          | =secnumdepth= > -2                          | upper-case Roman: =I=, =II=               |
| 0     | =\chapter=       | =secnumdepth= > -1 and in the main matter   | =1=; in the appendix =A=                  |
| 1     | =\section=       | =secnumdepth= ≥ 1                           | =1= (article), =1.1= (chaptered); =A= in an article's appendix |
| 2     | =\subsection=    | =secnumdepth= ≥ 2                           | =1.1=, =1.1.1=                            |
| 3     | =\subsubsection= | =secnumdepth= ≥ 3                           | parent's number, =.=, its own             |
| 4     | =\paragraph=     | =secnumdepth= ≥ 4                           | the same                                  |
| 5     | =\subparagraph=  | =secnumdepth= ≥ 5                           | the same                                  |

A starred command is not numbered. =\setcounter{secnumdepth}{n}= and
=\addtocounter{secnumdepth}{n}= change the depth. =\frontmatter= and
=\backmatter= stop the numbering of chapters (a section there is still
numbered, as =0.1= in a book's front matter); =\mainmatter= resumes it.
=\appendix= resets =section= and =subsection= in an article, =chapter=
and =section= otherwise, and switches the letters on. Each section's
parent is the nearest section before it with a smaller level.

** Counters

=\setcounter{c}{n}= and =\addtocounter{c}{n}= set any counter to an
integer. =\numberwithin{c}{w}= (amsmath) and =\counterwithin{c}{w}=
make =c= reset with =w= and print as =w='s number, a dot and its own;
=\counterwithout{c}{w}= undoes it.

** Equations

| Environment                                   | Numbers                                                         |
|-----------------------------------------------+-----------------------------------------------------------------|
| =equation=, =multline=                        | one                                                              |
| =align=, =gather=, =flalign=, =alignat=, =eqnarray= | one per line: each =\\= ends a line, and so does the end of the environment (so an empty line after a final =\\= is numbered, as amsmath numbers it) |
| the starred forms                             | none, but a =\tag= still gives its line a number                |
| =subequations=                                | steps =equation= once; the lines inside number as that number and a letter: =3a=, =3b= |

On a line, =\nonumber= or =\notag= takes the number away and =\tag{x}=
replaces it with =x=. A =\label= in a line gets that line's number.

#+begin_src latex
\begin{align}
  a &= b \label{eq:first} \\
  c &= d \nonumber \\
  e &= f \tag{$\star$}
\end{align}
#+end_src

Here =eq:first= is 1, the second line has no number and the third shows
=(⋆)=.

** Floats and captions

A =\caption= inside =figure=, =wrapfigure= or =subfigure= steps the
=figure= counter; inside =table=, =wraptable=, =longtable= or =subtable=
the =table= counter (starred forms too). Inside =subfigure= and
=subtable= a caption is lettered instead, =a=, =b=, … within its float.
A caption outside any float is not numbered. The model keeps each
float's captions with their short captions.

** Theorems

=\newtheorem{env}{Title}= declares a theorem-like environment with its
own counter; =\newtheorem{env}[other]{Title}= shares =other='s counter;
=\newtheorem{env}{Title}[within]= numbers it within =within= (=1.1=);
=\newtheorem*= declares an unnumbered one. Each environment of a declared
name in the text steps its counter; its note is its optional argument,
or a =[note]= at the very start of its body when the signature table
does not give the environment an optional argument.

#+begin_src latex
\newtheorem{theorem}{Theorem}[section]
\newtheorem{lemma}[theorem]{Lemma}
#+end_src

** Footnotes

Each =\footnote= steps the =footnote= counter (within =chapter= in
chaptered classes, printed without the chapter's number);
=\footnote[7]{…}= uses =7= as written and steps nothing.

** Labels

A =\label= takes the number and the kind of the last numbered thing in
scope, as =\refstepcounter= leaves them: a section, an equation (line),
a float's caption, a theorem or a footnote. An environment is a group:
at its end, what a =\label= would point at is restored to what it was
before it. The same holds for a footnote's text. A label with nothing
numbered before it has no number and the target =None=.

** Definitions

The model collects =\newcommand=, =\renewcommand=, =\providecommand=
(name, number of arguments, default of the optional first one, body),
=\def=, =\gdef=, =\edef=, =\xdef= (the number of =#= parameters),
=\DeclareMathOperator= (no arguments), =\newenvironment= and
=\renewenvironment= (arguments, default, begin and end code). The bodies
of definitions are templates: no label, citation or section inside them
counts. =\bibliography{a,b}= and =\addbibresource{a.bib}= give the
bibliography files, =.bib= added where missing; =\bibliographystyle=
gives the style.

* The rendered subset

The view (=kalem_core::latex_view::line_view=) draws each source line of
the file as the document reads. The same lines are drawn by the
graphical and the terminal editor. The rule that governs every
construct: away from the cursor a construct is drawn; when the cursor
is inside its source range (or at either end), it shows its source, so
what is edited is always the text itself. The source view (Ctrl+/)
shows the file as text, highlighted as LaTeX.

** Theorems and proofs

The =\begin= of an environment declared with =\newtheorem= shows "Title
N (note). ": the title and number bold, the note from the optional
argument or from =[…]= at the start of the body. Its =\end= line is a
delimiter line. =\begin{proof}= shows "Proof. " bold italic, or
"Proof (X). " for =\begin{proof}[X]=, and =\end{proof}= shows ∎.

#+begin_src latex
\begin{theorem}[Pythagoras]\label{thm:p}
  $a^2 + b^2 = c^2$.
\end{theorem}
\begin{proof}
  Trivial.
\end{proof}
#+end_src

In a =report= with =\newtheorem{theorem}{Theorem}[chapter]= in the
second chapter, the first line shows "*Theorem 2.1* (Pythagoras). ".

** Pictures

=\includegraphics[options]{name}= is drawn as the picture when its file
is found: =name= in the document's folder, then in each =\graphicspath=
folder; a name without an extension is tried with =.png=, =.jpg=,
=.jpeg=, =.pdf=, =.svg= and =.eps=, in that order. The size comes from
the first of these options present:

| Option                  | Size                                                                                                     |
|-------------------------+----------------------------------------------------------------------------------------------------------|
| =width=                 | a share of the line when it ends in =\textwidth=, =\linewidth=, =\columnwidth= or =\hsize= (=0.5\linewidth= is 50%, clamped to 1–1000%); otherwise a length in =cm=, =mm=, =in=, =pt= or =px=, at 96 pixels an inch |
| =height=                | a length as above; the width follows the picture's proportions                                           |
| =scale=                 | a share of the picture's own size                                                                        |

The graphical editor draws PNG, JPEG and SVG; a PDF or EPS picture shows
as its name. The terminal editor draws pictures through the kitty,
iTerm2 or sixel protocols where the terminal has one, and =[image: …]=
otherwise.

** Code, verbatim and comments

The bodies of the verbatim environments are monospace. =lstlisting= and
=minted= are code blocks colored by =kalem-highlight= in the language
their options name: =lstlisting='s =language== option (a
=[dialect]Name= form keeps =Name=), else the last
=\lstset{language=…}= in the document; =minted='s argument. =verbatim=
has no language and stays monospace. Comments (=%= to the end of the
line) are dimmed; so are =comment= environments and the text between
=\iffalse= and its =\fi=.

** What stays source, and how

Everything outside the tables above is drawn as its source:

- A control word outside the signature table and the formatting table
  is dimmed, away from the cursor. A command the signature table knows
  but the view does not render (=\label=, =\hspace=, =\usepackage=) is
  drawn in the surrounding style, not dimmed. Arguments are drawn as
  text, with their braces.
- The =\begin= and =\end= of an environment the view does not render
  show as source, the command dimmed.
- A formula the renderer cannot lay out shows as its source in a red
  frame, as in Org.

Some commands have no drawing of their own but count as rendered in the
coverage report, because they need none or have their effect elsewhere:
=\label=, =\begin=, =\end=, =\appendix=, =\frontmatter=, =\mainmatter=,
=\backmatter=, =\bibliography=, =\bibliographystyle=, =\noindent=,
=\par=, =\iffalse= and =\fi=. Their names show as source.

** The coverage report

=kalem check FILE.tex --unrendered= lists the commands and environments
of the document's body the view does not render, most frequent first
(=\foo= and =\begin{bar}= with their counts), and the share of the body
rendered. Commands whose names are not all letters and =@= are not
listed, and nothing inside a formula counts, since formulas are the math
renderer's. The share is computed over the body's non-blank characters:
every command or environment not rendered counts as source whole, with
its arguments and body. An environment counts as rendered when it is in
the table above, or when the model declares it as a theorem.

** Outline, table of contents and footnote list

The outline panel lists the sections of the file with their numbers,

* Mathematics

Formulas are typeset by org-math, Kalem's formula engine (RaTeX with the
KaTeX fonts), the same that typesets Org's LaTeX fragments. A formula
away from the cursor is drawn: inline math as a formula in the line,
=\[…\]=, =$$…$$= and the display environments (=equation=, =align=,
=gather=, =multline=, =eqnarray=, =alignat=, =flalign=, =displaymath=,
=math=, starred too) as displayed formulas. A display formula over
several lines, alone on its lines, is one math block, shown as one
formula on its first line with the other lines hidden until the cursor
enters it. The outermost math node is what is drawn; environments such
as =split= or =pmatrix= are drawn with the formula around them. While
the cursor is inside a formula, the formula is previewed under the
cursor, rendered in the graphical editor and as its Unicode
approximation in the terminal.

What the renderer receives (=math_source=) is the formula's source
with these changes:

1. =\label{…}=, =\nonumber= and =\notag= are taken out (the renderer has
   no =\label=).
2. In a display environment, each numbered line gets =\tag{N}= with the
   number the model gives it (a line with its own =\tag= keeps it), and
   the environment is renamed to its starred form, so that only these
   tags number it.
3. The definitions: first those of the packages the document loads that
   the renderer lacks (below), then the document's own =\newcommand=,
   =\renewcommand=, =\providecommand=, =\def= and =\DeclareMathOperator=
   definitions, as written, which win. This is what =#+LATEX_HEADER=
   lines do for Org.

For

#+begin_src latex
\begin{equation}
  E = mc^2 \label{eq:e}
\end{equation}

* Tables

A table environment is drawn as the shared grid (the one Org tables
use) when it is /simple/. The definition (=latex_table::simple=):

1. The environment is =tabular=, =tabular*=, =tabularx=, =tabulary=,
   =array= or =longtable=, and has its =\end=.
2. Its column specification is the last mandatory argument of =\begin=,
   and contains only:
   | Letter                  | Column                                |
   |-------------------------+---------------------------------------|
   | =l= =c= =r=             | aligned left, centered, right         |
   | =p{…}= =m{…}= =b{…}=    | left (the width's braces balanced)    |
   | =X= =L= =C= =R= =J=     | left                                  |
   | the vertical bar, spaces, tabs, line endings | nothing (ignored) |
   Anything else (=@{}=, =>{…}=, =*{3}{c}=, =S=) makes the table not
   simple.
3. Nothing but blanks follows the =\begin…= on its line, and the =\end=
   stands on a line of its own (blanks before it allowed).
4. Every line between them is a /rule line/ or a /row line/. There is no
   blank line.
   - A rule line holds only rule commands: =\hline=, =\toprule=,
     =\midrule=, =\bottomrule=, =\cline=, =\cmidrule=, =\addlinespace=,
     each with its optional =(…)=, =[…]= and ={…}=.
   - A row line holds one row: cells separated by the =&= outside
     braces, ended by =\\= (with an optional =[…]=), after which only rule
     commands may follow (they are drawn under the row). It has no =%=,
     no =\verb= or =\lstinline=, and its braces balance. At most as many
     cells as columns. Only the last row may lack its =\\=.
5. A cell that is all =\multicolumn{n}{spec}{text}= spans =n= columns,
   aligned as the first letter of its =spec=; a cell that is all
   =\multirow{n}[…]{width}{text}= (=width= may be =*=) shows its text in
   its cell. Any other cell containing =\multicolumn= or =\multirow=
   makes the table not simple.

#+begin_src latex
\begin{tabular}{l|cr}
  \toprule
  Name & Count & Share \\
  \midrule
  \multicolumn{2}{c}{Total} & 100\% \\
  \bottomrule
\end{tabular}
#+end_src

The grid is drawn away from the cursor, columns aligned as the
specification says, the rows before the first rule under a row as the
header; a rule written after a row's =\\= is drawn under that row. Each
cell's text is drawn as the view draws the line (formulas, emphasis,
chips). When the cursor enters the table it is its source, so edits and
the file's own alignment of =&= stay as written; Tab and Shift+Tab move
to the next and previous cell. A table that is not simple stays source.

** Formatting

=kalem fmt FILE.tex [--check] [--align]= changes only blanks: each line
indented by the environments around it (not =document=), with the
document's own step, the most common indentation the first line of an
environment adds to its =\begin= line (a document that does not indent
its environments keeps its indentation); runs of blank lines made one;
blanks at line ends removed; one line ending at the end. Verbatim text
(verbatim environment bodies and verbatim arguments) is not touched.
=--align= lines up the top-level =&= of the rows of =tabular=,
=tabularx=, =longtable=, =array=, =align=, =alignat=, =flalign=,
=eqnarray=, the matrices and =cases= written one row a line
(=\multicolumn= rows and nested environments left). =--check= changes
nothing and lists the files that would change.

* Building

/Build PDF/ (=latex.build=, F5) compiles the project's root document in
the background; =latex.build_on_save= builds on each save, one build at
a time; /Cancel Build/ (=latex.cancelBuild=) kills the program that runs.
=kalem latex build FILE= does the same on the command line.

** The engine

The first of these that applies:

1. =% !TEX program = NAME= or =% !TEX TS-program = NAME= among the first
   20 lines of the root document (=!= optional, any case).
2. The =latex.engine= setting (or =--engine= on the command line) unless
   it is =auto= or empty.
3. XeLaTeX when the project loads =fontspec=, =unicode-math= or
   =polyglossia=.
4. pdfLaTeX.

A name of step 1 or 2 means XeLaTeX when it is =xelatex=, LuaLaTeX when
it is =lualatex=, and pdfLaTeX for anything else.

** The tool

Looked for in =PATH=, in this order:

| Tool                              | When                                   | Command line (in the root's folder)                                                                          |
|-----------------------------------+----------------------------------------+--------------------------------------------------------------------------------------------------------------|
| =latexmk=                         | =latexmk= and the engine are installed | =latexmk -pdf -interaction=nonstopmode -file-line-error -halt-on-error -pdflatex= (or =-xelatex=, =-lualatex=) =[-outdir=DIR] FILE= |
| the engine alone                  | the engine is installed                | =ENGINE -interaction=nonstopmode -file-line-error [-output-directory=DIR] FILE=; then =biber STEM= when the run left =STEM.bcf=, or =bibtex STEM= when =STEM.aux= has =\bibdata{= (looked for beside the engine, then in =PATH=; run in the output folder); then the engine twice more after a bibliography run, once more without |
| =tectonic=                        | neither is installed                   | =tectonic --keep-logs [--outdir=DIR] FILE= (tectonic's own engine)                                           |

Without any of them, the build fails with "No LaTeX found: install TeX
Live, MacTeX, MiKTeX or tectonic". =latex.output_directory= (or
=--outdir=) names a folder relative to the root's, created if needed;
the PDF and the log are looked for there as =STEM.pdf= and =STEM.log=.

** The log

The log is read after the build:

- Lines of exactly 79 characters are joined with the next, as TeX wraps
  them.
- =FILE:LINE: MESSAGE= (=-file-line-error=; the file has no blank and an
  extension of one to four letters or digits) is an error at that file
  and line, whether the file is the document's or a package's.
- =! MESSAGE= is an error; its line is the =l.N= within the next 12
  lines; its file is the one the log was reading.
- A line containing =Warning:= is a warning, continued on the following
  lines that start with three spaces until the text ends with a period;
  its line comes from =input line N=, =at lines N= or =at line N=.
- A line starting with =Overfull= or =Underfull= is a bad box.
- The file being read is followed through the log's parentheses: =(= and
  a name opens a file, =)= closes it.
- A message naming a missing file (=File `x.sty' not found=) gets the
  command that installs it: =tlmgr install x= when =tlmgr= is in =PATH=
  (TeX Live), =mpm --install=x= when =mpm= or =miktex= is (MiKTeX).

The status bar gives the first error at its file and line with the count
of the others, or the PDF and the number of warnings. The problems are
kept with their files and show in each file of the project as
=latex-build= diagnostics. =kalem latex build= prints them as
=FILE:LINE: error|warning|info: MESSAGE= followed by the PDF's path, or
with =--format json= as an object with =root=, =pdf= and =problems=
(=file=, =line=, =severity=, =message=); it exits with 1 when there is an
error or no PDF.

* Limits and known gaps

What Kalem does not do today, from the code and the open items of the
work breakdown (group 2.7h of =todo.md=):

- *No corpus yet.* The rendered subset was chosen without the planned
  coverage study over arXiv sources (T2.7h.1), so no coverage target is
  set and the decision record =D30= is not written. The byte-exact round
  trip, the pandoc differential, compile-and-compare and the math
  snapshots run on the repository's fixtures, not on a corpus
  (T2.7h.30 to T2.7h.34, T2.7h.36). =kalem diff-pandoc= compares counts,
  not titles or text.
- *Parsing.* No catcode changes but =\makeatletter=; no signatures for
  the document's own macros; no verbatim environments beyond the fixed
  list; =\input file= without braces not read (see What the parser does
  not follow).
- *Projects.* No workspace setting for the root and no use of the
  project's file list in the root search (T2.7h.4). The outline panel
  lists only the sections of the file shown, though with the project's
  numbers.
- *Mathematics.* No table of unsupported macros yet (T2.7h.7). The
  definitions given to the renderer are cut from the edited file by the
  ranges of the model's macros, so in a file of a multi-file project
  macros defined in other files (the root's preamble) are not applied
  reliably. =\newenvironment= definitions are not given to the renderer.
- *Pictures.* PDF pictures (which need pdfium, T4.3.2) and EPS
  conversion are placeholders (T2.7h.8).
- *Tables.* =\multirow= is not drawn across its rows (T2.7h.9).
- *References and citations.* =\pageref= shows the key, as there are no
  pages; =\cpageref= stays source. In the view, bibliography files are
  resolved from the edited file's folder; =kalem check= resolves them
  from the root's, as LaTeX does.
- *Editing.* No nesting rules for formatting toggles inside other
  formatting, no dashes while typing, no style inference for blank lines
  and =\label= placement (T2.7h.15).
- *Completion.* No texlab bridge (T2.7h.17, which needs the language
  server plugin).
- *BibTeX.* No entries added from a DOI (T2.7h.19).
- *Building.* No PDF panel and no SyncTeX (T2.7h.24); tectonic is used
  only when no TeX engine is installed and is not downloaded on demand;
  no debounce beyond one build at a time (T2.7h.22). A build compiles
  the files as saved on disk.
- *Not started.* Typst as a sibling mode (T2.7h.25), working beside
  Overleaf (T2.7h.28), spell checking in LaTeX (T2.7h.29), the release
  checks (T2.7h.37).
