Kalem has two keymaps, chosen in the settings: Word-like keys, the
default, and Vim keys. On macOS, Command takes the place of Control in the
Word-like keys (Cmd+S saves).

The other keys are in the sections above, and in the command palette.

* Vim keys

With =editor.keymap_profile = "vim"=, every key is Vim's except the
leader keys, which are Doom Emacs's (=SPC f f=, =SPC p p=…, below). The
Word-like keys with Control or Alt are off wherever the Vim layer is on:
Ctrl+S, Ctrl+W, Ctrl+V and the others are Vim's (=:w= saves). Doom keeps
a few keys under Evil and so does Kalem: Alt with the arrows (Org's and
Markdown's structure moves, the tables' rows and columns), Control or Alt
with Enter, and Ctrl+Space for completion. On macOS, Command keeps the
Word-like keys (Cmd+S, Cmd+C, Cmd+V), as Doom's =s-= keys do, and Control
is Vim's.

What Vim does, Kalem does the same way, and the tests hold it to that:
=tests/vim/cases.json= has a few hundred key sequences, each run in Vim
itself (=tools/vim-expected.py=, a job of the continuous integration)
and in Kalem, and the text and cursor after them must agree. What is
there:

- Normal mode: every motion (=h j k l w b e ge W B E gE 0 ^ $ g_ | gm gM
  go gg G H M L f t F T ; , % ( ) { } + - _ Enter=), counts, the
  operators =d c y > < = g~ gu gU g?= with motions, text objects (=iw aw
  iW aW is as ip ap i( a( i[ a[ i{ a{ i< a< it at i" a" i' a' i` a`=, with
  counts, =d2aw=), =x X s S r R D C Y p P gp gP J gJ ~ u U Ctrl+R .=,
  =Ctrl+A= and =Ctrl+X= (decimal, =0x= hexadecimal, =0b= binary), =gi gI
  gv gn gN cgn=, =Ctrl+E Ctrl+Y zt zz zb=, =Ctrl+D Ctrl+U Ctrl+F Ctrl+B=.
- Marks =m= with =' `= and Vim's own marks (=''=, ='[=, =']=, ='<=,
  ='>=, ='.=, ='^=), the jump list (=Ctrl+O=, =Ctrl+I=) and the change
  list (=g;=, =g,=).
- Registers: ="a= to ="z= (="A= appends), ="0= the last yank, ="1= to
  ="9= the deletes of lines, ="-= the small ones, ="_= nothing, =".= the
  last insert, =":= the last command line, ="/= the last search, ="+=
  and ="*= the system clipboard. Macros: =q= records, =@= runs, =@@=
  again, =@:= the command line again.
- Visual mode: =v V= and Ctrl+V, =o=, =gv=, the operators, =r=, =p=
  (the replaced text goes to the unnamed register), =J=, Ctrl+A and
  =g Ctrl+A=, =I= and =A= on a block (=$= to the end of each line), and
  =.= repeats on as much text.
- Insert mode: Ctrl+W, Ctrl+U and Ctrl+H (=backspace= as
  =indent,eol,start=, stopping once where the insert started), Ctrl+R

- Search: =/= and =?= with Vim's patterns (=\<word\>=, =\(…\)=, =\|=,
  =\{n,m}=, =\v=, =\V=, =\zs=, =\ze=, =\c=), =n N * # g* g#=.

  =/pat/=, =?pat?=, offsets, ='<,'>= from visual mode): =:s= with its

  =:co=, =:j=, =:>=, =:<=, =:norm=, =:sort= (=n=, =u=, =i=, =r=, a
  pattern, =!=), =:k= and =:mark=, =:u=, =:red=, =:left=, =:retab=,
  =:==, =:p=, =:reg=, =:marks=, =:noh=; =:set= for =shiftwidth=,
  =tabstop=, =softtabstop=, =expandtab=, =autoindent=, =ignorecase=,
  =smartcase=, =wrapscan=, =joinspaces=, =nrformats= (with =no=, =inv=,

  =:x=, =:qa=, =:wqa=, =:e FILE= (=:e= alone asks), =:e!= (Revert to

  =:only=, =:new=; =:Ex=, =:E=, =:Explore= and =:Dired= open the file
  manager, and =:Projects= the projects. =gt= and =gT= go to the next
  and previous document.

Kalem's defaults differ from Vim's where Vim's own are kept for
compatibility with Vi: =autoindent= is on, =shiftwidth= is 2 with
=expandtab= and =softtabstop= following it, =backspace= is
=indent,eol,start=, =nrformats= is =bin,hex= and =joinspaces= is off;
=:set= changes them for the document. What Vim has that Kalem does not:
Vim script, plugins, =:help=, folds by Vim's commands (Kalem folds Org
headings with Tab), the =:!= filter and =gq= formatting.

=SPC u= is Emacs's universal argument: the next command runs four times,
=SPC u SPC u= sixteen, and digits typed after =SPC u= give the count
(=SPC u 1 2=); Escape drops it. A command that opens a list or asks
for a file runs once.

=SPC w= divides the window into panes, as Doom does: =SPC w v= and
=SPC w s= split it beside and below, =SPC w h j k l= go to the pane in
that direction, =SPC w H J K L= move the pane to that edge of the window,
=SPC w w= and =SPC w p= go to the next and the last pane, =SPC w o=
shows only this pane and again all of them, =SPC w ==, =SPC w + - < >=
balance and resize (with =SPC u= for a count), =SPC w x= swaps, =SPC w r=
rotates, and =SPC w u= and =SPC w U= undo and redo the layout. The
focused pane shows the active document; the new pane of a split shows
the document shown before it, and when only one document is open a split
shows it beside itself (the split view). Opening a document another pane
shows swaps the two. A click in a pane focuses it. Both editors have
panes; in the terminal a rule with the document's name divides them. In
the Emacs keymap =C-x 2=, =C-x 3=, =C-x o=, =C-x 0= and =C-x 1= do the
same.

=SPC TAB= keeps workspaces, named sets of the window's documents, as
Doom does: =SPC TAB n= starts one (=SPC TAB N= with a name), =SPC TAB
TAB= or =SPC TAB .= chooses one, =SPC TAB [= and =SPC TAB ]= go to the
one before and after, =SPC TAB 1= to =9= by place, =SPC TAB `= to the
last, =SPC TAB r= renames and =SPC TAB d= deletes it. The list of open
files and the document cycle show the workspace's documents; each
workspace keeps its panes and the document it showed. Deleting a
workspace closes nothing: its documents join the workspace shown next.
=SPC TAB s= saves the workspace's documents (a session called
=workspace-NAME=), =SPC TAB l= opens a saved one in a new workspace, and
=SPC TAB x= deletes a saved one. The status bar names the workspace when
there are several.

A session is the open documents, the cursor in each, the one shown and
the project. Kalem saves the session called =last= when it quits, which
=SPC q l= restores, and on start too when =editor.restore_session= is
on. =SPC q S= asks for a name (or a file path ending in =.json=);
the sessions live in =sessions/= in Kalem's state folder. Restarting
waits until the changed documents are saved or closed.

The toggles that are settings (line numbers, markup characters, big
text) save the setting, so the settings file and the key agree.

A document follows its file when the file is renamed or moved, from
here or from the file manager, and closes when the file goes to the
trash, unless it has unsaved changes.

=editor.vim.leader= makes another key the leader (="\\"= or =","=, say).

In Org documents, =>>= and =<<= demote and promote headings and indent
list items.

=editor.vim.modes= limits Vim keys to some kinds of documents: =org=,
=markdown=, =csv=, =latex=, =text= (plain text, code and BibTeX) and
=directory= (the file manager); for example =["text"]= for plain text
only.

* Your own keys

Every key can be changed. =keymap.json= in the settings directory changes
keys:

#+begin_src json
[
  // Ctrl+Shift+W sets the tag "work".
  { "keys": "ctrl+shift+w", "command": "org.tags.set",
    "args": { "tags": ["work"] }, "when": "onHeadline" },
  // No Ctrl+B for bold.
  { "keys": "ctrl+b", "command": "-org.emphasis.bold" },
  // Two-key sequences, Emacs style.
  { "keys": "C-c C-t", "command": "org.todo.cycle" },
  // Vim keys: SPC p t lists the project's recent files; no SPC q q.
  { "keys": "leader p t", "command": "project.recentFiles", "when": "vimCommand" },
  { "keys": "leader q q", "command": "-app.quit" }
]
#+end_src

=kalem commands= lists the command IDs (the palette shows titles, and
finds a command by its ID too). =leader= stands for the Vim leader.
=docs/keymaps/emacs.json= is a complete keymap with Emacs Org mode keys,
to copy into =keymap.json=.

Every command serves some types of text: all of them, a list, or all but
some. The type is the one at the cursor, innermost first: a source
block's language in an Org document (=python=), =latex= in a formula, the
file's kind (=org=, or =klm= for a =.klm= file, which Org's commands
serve too), a file's language (=rust=), =markdown=, =csv=, =text=. So
Ctrl+B makes bold text in Org and does nothing in a Python block, and
Alt+Up moves lines in code, source blocks included, but moves headings,
items and rows in Org. A binding can use the type too: ="when":
"textType == python"=; a type Kalem does not know is reported with the
other problems of the keymap. =kalem commands --type org= lists the
commands a type has, with their scope and keys.

* Keys in a terminal

A terminal without the kitty keyboard protocol cannot send some keys:
Ctrl+Enter arrives as Enter, Ctrl+Shift+P as Ctrl+P, and Command never
arrives. The terminal editor then uses other keys for those commands,
and the palette and menus show the keys it uses:

| Keys                          | In such a terminal              |
|-------------------------------+---------------------------------|
| Ctrl+Enter (Cycle TODO State) | Ctrl+T                          |
| Ctrl+, (Settings)             | Alt+,                           |
| Shift+Enter (line break)      | Ctrl+J                          |
| Ctrl+Shift+Z (Redo)           | Ctrl+Y                          |
| Ctrl+Shift+P (palette)        | Ctrl+G (and F1)                 |
| Ctrl+Tab, Ctrl+Shift+Tab      | Ctrl+PageDown, Ctrl+PageUp      |
| Ctrl+/ (source view)          | Ctrl+_                          |

Other Control keys such a terminal cannot send (with Shift, with a
digit, Ctrl+.) become Alt and the same key: Ctrl+Shift+T is Alt+T,
Ctrl+1 is Alt+1. A key with no such substitute, or whose substitute
another binding already has, is left out in such a terminal. A binding
in =keymap.json= can name its terminal key with
="terminalKeys": "alt+w"=.

In a terminal, keys with Alt reach Kalem only when the terminal sends
them: in macOS Terminal and iTerm2, set Option to act as Meta (Terminal:
Settings, Profiles, Keyboard, "Use Option as Meta key"; iTerm2: Profiles,
Keys, "Left Option key: Esc+"). Terminals with the kitty keyboard protocol
(kitty, WezTerm, Ghostty, foot) send every key as it is.
