Kalem has two keymaps, chosen in the settings: Word-like keys, the
default, and Vim keys. On macOS, Command takes the place of Control in
the Word-like keys (Cmd+S saves).

* Word-like keys

| Keys                   | Command                               |
|------------------------+---------------------------------------|
| Ctrl+S, Ctrl+Shift+S   | Save, Save As                         |
| Ctrl+Z, Ctrl+Y         | Undo, Redo (also Ctrl+Shift+Z)        |
| Ctrl+X, Ctrl+C, Ctrl+V | Cut, Copy, Paste                      |
| Ctrl+A                 | Select All                            |
| Shift+Enter            | Line break within a paragraph         |
| Ctrl+,                 | Settings                              |
| Ctrl+Q                 | Quit                                  |
| Ctrl+O, Ctrl+N, Ctrl+W | Open, New, Close document             |
| Ctrl+Shift+P, F1       | Command palette (Ctrl+G in terminals) |

The other keys are in the chapters of what they do, and in the command
palette.

* Vim keys

With =editor.keymap_profile = "vim"=, every key is Vim's: the modes,
motions, operators, text objects and counts, registers and macros,
marks with the jump and change lists, search with Vim's patterns, and
the command line with ranges, =:s=, =:g=, =:sort=, =:set= and the file
and window commands (=:w=, =:e=, =:sp=, =:bn=, =:Ex= for the file
manager, =:Projects=). Some five hundred key sequences in
=tests/vim/cases.json= are run in Vim itself and in Kalem, and the text
and cursor after them must agree. Not there: Vim script, plugins,
=:help=, Vim's fold commands (Tab folds Org headings), the =:!= filter
and =gq=.

=:q= closes the pane when the window is split, else the document, as a
tab closes: Kalem stays open, an empty document taking the last one's
place, and quits from =:q= only when nothing is left to close (in the
terminal, from the last document, as Vim does). =:q!= closes the
document losing its changes and no other's; =:qa= quits, =:qa!=
quits without saving after asking.

The Word-like Control and Alt keys are off where the Vim layer is on,
except, as in Doom Emacs, Alt with the arrows (structure moves, table
rows and columns), Control or Alt with Enter, and Ctrl+Space for
completion; on macOS, Command keeps the Word-like keys. In Org
documents =>>= and =<<= demote and promote headings and indent list
items. Kalem's defaults differ from Vim's where Vim keeps Vi's:
=autoindent= is on, =shiftwidth= is 2 with =expandtab=, =backspace= is
=indent,eol,start=, =nrformats= is =bin,hex= and =joinspaces= is off;
=:set= changes them for the document. =editor.vim.leader= makes
another key the leader, and =editor.vim.modes= limits Vim keys to some
kinds of documents: =org=, =markdown=, =csv=, =latex=, =text= and
=directory=.

** The leader

Space is the leader, as in Doom Emacs. Press it and wait a moment
(=keys.hints_delay=, 400 ms): a panel shows what can follow, in Doom's
groups, with the keys Kalem does not bind yet marked "(later)" or
"(plugin)". The panel follows any prefix, =C-x= and =C-c= of the Emacs
keys too; =keys.hints = false= turns it off. The keys you will use
first:

| Keys                 | Command                                   |
|----------------------+-------------------------------------------|
| =SPC p p=            | Switch Project                            |
| =SPC SPC=, =SPC p f= | Find File in Project                      |
| =SPC /=              | Search in Project                         |
| =SPC ,=, =SPC b b=   | Switch Document                           |
| =SPC f f=, =SPC .=   | Open a file by path (a new name makes it) |
| =SPC f s=, =SPC b k= | Save; Close Document                      |
| =SPC o -=, =SPC p P= | File manager; projects                    |
| =SPC c S=, =SPC o P= | Outline; the file in the folder tree      |
| =SPC s s=            | Search lines, the cursor following        |
| =SPC :=              | Command palette                           |
| =SPC t z=, =SPC w v= | Focus mode; split view                    |
| =SPC q l=, =SPC q q= | Restore the last session; quit            |
| =SPC h k=            | What the next keys run                    |

=SPC u= is Emacs's universal argument: the next command runs four
times, =SPC u SPC u= sixteen, digits after =SPC u= give the count, and
Escape drops it. Every key of Doom's leader map, and what it does in
Kalem or why it does not yet, is in the table at the end of this
chapter. A key does what Doom's does wherever Kalem can; where Doom's
command has no counterpart in Kalem, the key may run one of Kalem's
own, marked "Kalem" in the table. With Doom's =:os macos= keys, =SPC o
o= and =SPC o O= show the file and the project in Finder (the system's
file manager elsewhere), =SPC o i= opens a terminal there.

** Panes, workspaces and sessions

=SPC w= divides the window into panes, as Doom does: =SPC w v= and =SPC
w s= split it beside and below, =SPC w h j k l= go to the pane in that
direction, =SPC w H J K L= move the pane to that edge, =SPC w o= shows
only this pane and again all, =SPC w == balances, =SPC w x= swaps,
=SPC w u= and =SPC w C-r= undo and redo the layout. A click focuses a pane; the new pane of a
split shows the document shown before it, or the same document beside
itself when only one is open. Both editors have panes; in the
terminal a rule with the document's name divides them.

=SPC TAB= keeps workspaces, named sets of the window's documents, each
with its panes: =SPC TAB n= starts one, =SPC TAB TAB= chooses one, =SPC
TAB [= and =SPC TAB ]= go to the one before and after, =SPC TAB 1= to
=9= to one by its place and =SPC TAB 0= to the last, =SPC TAB r=
renames and =SPC TAB d= deletes it (its documents join the next
workspace); =SPC TAB s= and =SPC TAB l= save and restore one as a
session.

A session is the open documents, the cursor in each, the one shown
and the project. Kalem saves the session =last= when it quits; =SPC q
l= restores it, and so does starting when =editor.restore_session= is
on. =SPC q S= saves a session by name, and =SPC q L= restores one;
they live in =sessions/= in Kalem's state folder.

* Your own keys

=keymap.json= in the settings directory changes any key:

#+begin_src json
[
  // Ctrl+Shift+W sets the tag "work".
  { "keys": "ctrl+shift+w", "command": "org.tags.set",
    "args": { "tags": ["work"] }, "when": "onHeadline" },
  // No Ctrl+B for bold.
  { "keys": "ctrl+b", "command": "-org.emphasis.bold" },
  // Two-key sequences, Emacs style.
  { "keys": "C-c C-t", "command": "org.todo.cycle" },
  // Vim keys: SPC p t lists the project's recent files; no SPC q q.
  { "keys": "leader p t", "command": "project.recentFiles", "when": "vimCommand" },
  { "keys": "leader q q", "command": "-app.quit" }
]
#+end_src

=kalem commands= lists the command IDs, and the palette finds a
command by its ID too. =leader= stands for the Vim leader.
=docs/keymaps/emacs.json= is a complete keymap with Emacs's Org keys,
to copy from.

Every command serves some types of text. The type is the one at the
cursor, innermost first: a source block's language (=python=), =latex=
in a formula, the file's kind (=org=, =markdown=, =csv= or =text=), a
file's language (=rust=). So
Ctrl+B makes bold text in Org and does nothing in a Python block, and
Alt+Up moves lines in code but headings, items and rows in Org. A
binding can use the type: ="when": "textType == python"=. =kalem
commands --type org= lists the commands of a type with their scope
and keys.

* Keys in a terminal

A terminal without the kitty keyboard protocol cannot send some keys:
Ctrl+Enter arrives as Enter, Ctrl+Shift+P as Ctrl+P, and Command never
arrives. The terminal editor then uses other keys, which the palette
and menus show:

| Keys                          | In such a terminal         |
|-------------------------------+----------------------------|
| Ctrl+Enter (Cycle TODO State) | Ctrl+T                     |
| Ctrl+, (Settings)             | Alt+,                      |
| Shift+Enter (line break)      | Ctrl+J                     |
| Ctrl+Shift+Z (Redo)           | Ctrl+Y                     |
| Ctrl+Shift+P (palette)        | Ctrl+G (and F1)            |
| Ctrl+Tab, Ctrl+Shift+Tab      | Ctrl+PageDown, Ctrl+PageUp |
| Ctrl+/ (source view)          | Ctrl+_                     |

Other Control keys such a terminal cannot send become Alt and the same
key (Ctrl+Shift+T is Alt+T, Ctrl+1 is Alt+1); a binding in
=keymap.json= can name its own with ="terminalKeys": "alt+w"=. Alt
reaches Kalem only when the terminal sends it: in macOS Terminal, set
"Use Option as Meta key" (Settings, Profiles, Keyboard); in iTerm2,
"Left Option key: Esc+" (Profiles, Keys). Terminals with the kitty
keyboard protocol (kitty, WezTerm, Ghostty, foot) send every key as it
is.
