Kalem is a fast, open source editor for plain-text documents. It opens
a file as what it is, Org, Markdown, LaTeX, CSV, BibTeX or code, shows
it the way it reads, and writes back only what you changed. One editor
runs in a window and in a terminal, and every operation on a document
is also a command on the command line.

* Text first

The file on disk is the truth. Kalem keeps no database, no container
format and no sidecar files: the document is the text file you see in
=git diff= and in any other editor. Bold reads as bold, a table is a
grid, a formula is typeset, and under them the file is the same plain
text it was. There is nothing to export before a colleague can read
your work, and nothing to lose if you stop using Kalem.

* Every format as itself

Kalem never converts a file to open it and never saves it as another
format. Conversion is a command you run on purpose, /Export/, /Convert
to Org/ or =kalem export=, which writes a new file and leaves the old
one alone. Three rules hold for every format (Part II explains them):

1. *Ranges, never text.* A mode reads the file into ranges; an edit
   replaces only the characters it changes. The file is never written
   back from a tree, so untouched parts stay byte for byte: spacing,
   comments, line endings, a byte order mark.
2. *No extension.* Kalem writes nothing into a file that its standard
   does not define. A Markdown file gets no font menu, a CSV file no
   formatting.
3. *Unknown constructs stay visible.* What Kalem does not understand is
   shown as the source it is, never hidden or guessed.

* The formats

Five formats are built in, each checked against a reference
implementation or test suite, its /oracle/
([[file:../part-2/overview.org][Standard modes and their oracles]]).

| Format          | Opens as                                                 | Where in this book  |
|-----------------+----------------------------------------------------------+---------------------|
| Org             | A document; tables with formulas, TODO states, export    | [[file:writing-in-org.org][Writing in Org]], [[file:../part-2/org.org][Org]] |
| Markdown        | A document; task lists, tables, front matter, wiki links | [[file:../part-2/markdown.org][Markdown]]            |
| LaTeX           | A document; formulas, references, citations, PDF builds  | [[file:latex-files.org][LaTeX files]], [[file:../part-2/latex.org][LaTeX]]  |
| CSV, TSV        | A grid with sorting, filters and statistics              | [[file:csv-files.org][CSV files]], [[file:../part-2/csv.org][CSV]]      |
| BibTeX          | A grid of entries                                        | [[file:../part-2/bibtex.org][BibTeX]]              |
| Everything else | Plain text, colored by its language                      | [[file:plain-text-and-code.org][Plain text and code]] |

Every other format is to be a plugin: more text formats, viewers for
files that are not text (PDF, Word, Excel, images), language servers.
A plugin is compiled Rust, run as a WebAssembly component with its
own memory, a memory limit, a time budget and only the permissions it
declares, so a plugin cannot freeze the editor and one that fails is
disabled instead of taking Kalem down. Kalem ships no JavaScript, Lua
or Lisp interpreter; configuration is data, in TOML and JSON. The
plugin runtime is phase 3 of the roadmap and is not built yet;
[[file:../part-4/overview.org][The extension model]] says what can be changed today and
[[file:../part-4/plugins.org][Plugins]] has the design.

* Fast

Kalem is one static binary with nothing to interpret. On an Apple M1
Max it starts to its first frame in 148 ms, opens a 1 MB document in
184 ms, draws a keystroke in 8.7 ms, and uses 47 MB of memory with an
empty document. [[file:../part-5/performance.org][Performance]] has every target, the method and the
scripts that repeat the measurement.

* Two editors and a command line

The graphical and the terminal editor share one core: the same
commands, keys, settings, menus and views. The terminal editor draws
formulas, images and tables too, so a document reads the same over
SSH as on the desktop; what it cannot show is listed in
[[file:../part-5/terminal-parity.org][Terminal parity]]. Every document operation is also a command-line
tool, for scripts and CI: [[file:the-command-line.org][The command line]].

* A power editor's tools

Word-like keys by default and Vim keys as an option, with Doom Emacs's
leader keys, panes, workspaces and sessions ([[file:keys.org][Keys]]). A file manager
([[file:the-file-manager.org][The file manager]]), projects and find in files ([[file:documents-and-projects.org][Documents and projects]]),
a command palette and bookmarks ([[file:finding-and-commands.org][Finding and commands]]), an outline,
focus mode and narrowing ([[file:views.org][Views]]). Everything is a command with a
configurable key, and configuration is data that Kalem checks when it
reads it ([[file:settings.org][Settings]]). Kalem borrows these tools from Emacs, and that
is where the debt ends: it is made for anyone with text files.

* The Kalem format, optional

For documents the standard formats cannot carry, letters, papers,
theses and books with page-quality output, Kalem is designing a format
of its own, =.klm=: one command syntax, Org's outline and tasks, LaTeX
mathematics, tables with formulas, and styles and page layout in a
stylesheet, with a specification and a conformance suite (Part III).
It is a track beside the standard formats, which come first, and Kalem
never converts your files into it.

* What Kalem is not

Not a Microsoft Office clone: Word files will open through a plugin
later, and go through pandoc today. Not a page layout tool, a full
spreadsheet or a visual slide designer. Not a full IDE: language
servers come as plugins, and the core knows no programming language.
Not an Emacs: no Elisp, no agenda settings by the hundred;
[[file:../part-5/kalem-and-emacs.org][Kalem and Emacs]] says what is taken from it and what is left out. Not a
collaboration service: files and git are enough. The design document
lists the
[[https://github.com/getkalem/kalem/blob/main/docs/design_document.md#14-non-goals][non-goals]] in full.
