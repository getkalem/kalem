#+TITLE: Kalem user manual
#+SUBTITLE: Version 0.1
#+STARTUP: content

Kalem is an editor for Org files that looks like a word processor. Bold
text is bold, headings are large, tables are grids and links are links,
while the file on disk stays plain Org text that Emacs reads and writes
the same way. Kalem runs as a desktop application and in a terminal, and
it has command-line tools for scripts and CI.

* Installing

** From a release

Release archives hold one program, =kalem=. Put it on your =PATH=.

- macOS :: =Kalem.app= is not signed yet. The first time, open it with
  right-click and /Open/, and confirm.
- Terminal-only build :: an archive without the graphical editor, for
  servers and minimal systems.

** From source

With Rust 1.88 or later:

#+begin_src sh
cargo install --path crates/kalem
# Terminal editor and command-line tools only:
cargo install --path crates/kalem --no-default-features --features tui
#+end_src

On Linux the graphical editor needs the development files of xkbcommon,
Wayland, X11 (xcb), fontconfig and freetype.

On macOS, =tools/macos-app.sh= builds =Kalem.app=.

* Starting

| Command              | What it does                                                                 |
|----------------------+------------------------------------------------------------------------------|
| =kalem FILE=         | Opens the file in the graphical editor, or in the terminal without a display |
| =kalem gui FILE=     | The graphical editor                                                         |
| =kalem tui FILE=     | The terminal editor (also =kalem -t FILE=)                                   |
| =kalem tui --detect= | What the terminal can do: colors, images, keyboard                           |
| =kalem check FILE=   | Command-line tools: see [[*The command line][The command line]]                                     |

A file that does not exist yet is created when you save. A new file needs
an extension, such as =notes.org=; a bare word is taken for a mistyped
command.

* Writing in Org

The editor shows the document as it will read: markup such as the stars
around bold text is hidden, and appears when the cursor is on it, so you
can always see and change what is in the file.

Kalem writes two kinds of file. A =.org= file is Org as Emacs knows it,
and Kalem keeps it so: it never writes its own additions into it, so a
co-author in Emacs never meets a line only Kalem understands. A =.klm=
file is a /Kalem document/: Org with Kalem's word processor formatting
(fonts, sizes, colors, alignment, paragraph spacing), all written through
Org's own extension points, so a =.klm= renamed to =.org= is still an Org
file Emacs opens (=(add-to-list 'auto-mode-alist '("\\.klm\\'"
. org-mode))= opens it without renaming). The status bar says which kind
the document is. Formatting a =.org= file offers a choice: /Make Kalem
Document/ saves it as =.klm= beside it (links to it in the project follow
the new name), and /Allow Kalem's Formatting in This File/ adds
=#+KALEM: markup=yes= to it; the setting =org.allow_kalem_markup= in a
folder's =.kalem/settings.toml= allows it for all its files.

** Headings

A line that starts with stars is a heading: =* Chapter=, =** Section=.
Ctrl+1 to Ctrl+6 make the current line a heading of that level, Ctrl+0
makes a heading plain text again. Alt+Left and Alt+Right promote and demote
a heading; with Shift, its whole subtree. Alt+Up and Alt+Down move a
subtree past its neighbors.

Tab on a heading folds and unfolds it; Shift+Tab on a heading cycles the
whole document between overview, contents and everything.

** Text formatting

| Keys         | Formatting     | In the file   |
|--------------+----------------+---------------|
| Ctrl+B       | Bold           | =*bold*=      |
| Ctrl+I       | Italic         | =/italic/=    |
| Ctrl+U       | Underline      | =_underline_= |
| Ctrl+Shift+X | Strike-through | =+gone+=      |
| Ctrl+Shift+K | Code           | =~code~=      |

With a selection, the keys format it, or remove the formatting when it is
already there. Deleting a marker character turns the formatting into
plain text, and the status bar says so.

** Lists and checkboxes

Start a line with =- = for a list or =1. = for a numbered one. Enter
continues the list; Enter on an empty item ends it. Tab and Shift+Tab
indent and outdent an item, Alt+Enter inserts one, Ctrl+Shift+L cycles the
bullet style. Ctrl+Shift+C adds, checks and unchecks a checkbox =[ ]=, and
a click on a checkbox toggles it. Statistics cookies such as =[1/3]= are
kept up to date.

** Tables

Ctrl+Shift+T inserts a table. A line starting with =|= is a table row.
Typing keeps the columns aligned. Tab and Shift+Tab move between fields,
Enter goes to the next row. With Alt: Up and Down move rows, Left and
Right move columns; with Alt+Shift: Down inserts a row, Up deletes one,
Right inserts a column, Left deletes one. Away from the cursor, a table is
drawn as a grid.

Pasting cells from a spreadsheet makes a table.

*** Formulas

A =#+TBLFM:= line under a table computes fields, as in Emacs: =$4=$2*$3=
fills the fourth column of every row with the product of the second and
third, =@>$4=vsum(@2..@-1)= puts a sum in the last row. F9 (=C-c *= in
the Emacs example keymap) recalculates the table and aligns it. With the
setting =org.table_auto_recalc = true=, or =#+KALEM: recalc=auto= in the
document, leaving a field with Tab, Shift+Tab or Enter recalculates too;
=recalc=manual= keeps a document on F9 whatever the setting says.

Formulas are Emacs Calc formulas and give the results Emacs gives: the
same references (=$2=, =@3$1=, =@I..@II=, =$-1=, =remote(name, @2$3)=,
column names from a =!= row, parameters from =$= rows, =#+CONSTANTS=),
the same functions (=vsum=, =vmean=, =vmedian=, =round=, =if=…), the
same flags (=;%.2f=, =;N=, =;E=, =;T= for durations such as =8:30=), and
dates: =$2-$1= between two timestamps is a number of days. Emacs Lisp
formulas (='(...)=) are kept but not computed; Kalem says which ones.

From the command line, =kalem table recalc FILE= recalculates every table
of a file (=--iterate= until nothing changes, =--check= for CI).

** Fonts, sizes and colors

Kalem formats text as a word processor does, beyond what Org has: the
font, the size, the text color and a highlight color of any part of a
paragraph or heading, and the alignment of paragraphs. Select text (or put
the cursor in a word) and use the toolbar: the font and size menus, A+ and
A−, the color and highlight swatches, the four alignment buttons, and Clear
Formatting. The same commands are in the palette and on Word's keys:

| Keys               | Command                                   |
|--------------------+-------------------------------------------|
| Ctrl+] and Ctrl+[  | Grow and shrink the font (also Ctrl+Shift+> and <) |
| Ctrl+L, Ctrl+E     | Align left, center                        |
| Ctrl+R, Ctrl+J     | Align right, justify                      |
| Ctrl+Space         | Clear formatting                          |

This is for Kalem documents (=.klm=, see above). The file stays an Org
file that Emacs opens: a formatted part is written
between =@@kalem:size=14 color=#c00000@@= and =@@kalem:end@@=, and a
right-aligned paragraph has =#+ATTR_KALEM: :align right= above it. Kalem
hides these; the source view (Ctrl+/) shows them. Emacs shows them as they
are and leaves them out when it exports. Every Org file opens in Kalem as
in Emacs; a file that uses these additions looks plainer in Emacs.

The whole document's font, size and line spacing are /Document Font/,
/Document Font Size/ and /Line Spacing/ (also the ↕ menu of the
toolbar), kept in a =#+KALEM:= line at the top, such as
=#+KALEM: font="Georgia" size=12 spacing=1.5=. Space before and after a
paragraph (/Space Before Paragraph/, /Space After Paragraph/, also in the ↕
menu) is =#+ATTR_KALEM: :before 12 :after 6=, in points; the font menu
searches the fonts as you type, and the color menus keep the colors used
lately.

In a terminal, colors and alignment show, fonts and sizes do not; there
Alt+= and Alt+- grow and shrink the font.

** Formulas in the text

LaTeX formulas show typeset: =$E=mc^2$=, =\(a^2+b^2\)=, =$$\sum_i x_i$$=
and environments such as =\begin{align}= … =\end{align}=. With the
cursor inside a formula you see its source, with a preview of the result
beside it as you type; a click on a formula takes you into its source. A
formula that cannot be typeset shows its source in a red frame. The
commands =\newcommand=, =\renewcommand=, =\def= and =\DeclareMathOperator=
in =#+LATEX_HEADER:= lines work in the document's formulas. /Toggle
Formula Preview/ shows every formula as its source.

In the terminal, formulas are approximated with Unicode characters
(=x²=, =α=). Terminals that draw images (kitty, iTerm2, WezTerm, sixel)
show displayed formulas and environments typeset.

** Links

Ctrl+K inserts a link. Typing =[[= offers the document's headings and
targets. Ctrl-click (Cmd-click on macOS) opens a link: web links in the
browser, file links in Kalem or their application, internal links jump.

** Footnotes

/New Footnote/ (Ctrl+Alt+F, or Insert > Footnote) writes the next free
number, =[fn:1]=, at the cursor and starts its definition under the
=Footnotes= heading at the end of the document (made when missing), with
the cursor there; =org.footnote_section = ""= puts each definition at
the end of its section instead. /Go to Footnote Definition or Reference/
goes from a reference to its definition and from a definition's label
back to its closest reference. /Renumber Footnotes/ numbers them again
in reading order, /Sort Footnote Definitions/ puts the definitions in
the order of their references, /Normalize Footnotes/ does both and moves
inline footnotes out, and /Delete Footnote/ removes a footnote with all
its references. These are Emacs's =org-footnote= commands and give the
same text. With the cursor on a reference, the status bar shows the
footnote's text; in the graphical editor, so does a tooltip under the
mouse.

** Pictures

A link to a picture without a description, such as =[[file:cat.png]]=,
shows the picture in its place (PNG, JPEG, GIF, WebP, BMP, TIFF and
SVG), no wider than the text; with the cursor on it you see the link.
=#+ATTR_ORG: :width 300= (pixels) or =:width 50%= above the paragraph sets
its width. =[[attachment:plan.png]]= finds the file in its heading's
attachment folder as =org-attach= keeps it: the =DIR= property, else
=data/= and the heading's =ID=.

A picture pasted from the clipboard (a screenshot), or picture files
pasted or dropped on a saved document, are copied into a folder beside
it, =NAME_assets= for =NAME.org=, and linked where the cursor or the
mouse is; pictures already in the document's folder are linked where
they are. The terminal editor draws pictures that are alone on their
line where the terminal draws images, and a file dropped on the terminal
is linked the same way.

** Tasks, dates and tags

Ctrl+Enter cycles a heading through its TODO states (=TODO=, =DONE=, or
the states of the document's =#+TODO= line); Shift+Left and Shift+Right
step through them, Shift+Up and Shift+Down change the priority.

/Schedule/ (Ctrl+Alt+S) and /Set Deadline/ ask for a date (a calendar in
the graphical editor; =today=, =+3d=, =friday=, =2026-10-05 14:30= and
the like typed) and write =SCHEDULED:= or =DEADLINE:= on the heading's
planning line, as Emacs's =org-schedule= and =org-deadline= do: a time
of day when you give one, a repeater or warning typed after the date
(=2026-10-05 +1w=, =friday .+2d -3d=), the old timestamp's repeater kept
otherwise, and =CLOSED:= taken away. /Remove Schedule/ and /Remove
Deadline/ take them off again.

With =org.enforce_todo_dependencies= on, a task cannot be marked done
while a task below it is still open, and under a heading with the
=ORDERED= property (Toggle Ordered Subtasks) each task waits for the ones
before it; with =org.enforce_todo_checkbox_dependencies=, it also waits
for its checkboxes. A =NOBLOCKING= property lifts both for one task.
=org.todo_state_tags_triggers= changes tags with the state: the entry
="done: -next +closed"= removes =next= and adds =closed= when a task is
done (=todo= stands for any open state, a keyword for itself, and nothing
before the colon for no keyword). These are the settings of the same names
in Emacs, so a file behaves the same in both.

Alt+Shift+D inserts a date: a calendar opens on the date under the cursor
or today. Arrows move by day and week, Page Up and Page Down by month, and
you can type a date such as =+3d=, =fri 10:00=, =tomorrow= or
=2026-12-24=. Ctrl+Shift+D inserts the current time stamp.

Typing a colon at the end of a heading offers the tags of =#+TAGS= and
the tags in use; the chosen tag is aligned at the right edge.

** Completion

Typing =#+= offers keywords and blocks (=#+begin_src=, =#+title:=), =[[=
link targets, =[fn:= footnote labels. Up and Down choose, Enter or Tab
inserts, Escape closes.

** Paste

Paste (Ctrl+V) converts: cells from a spreadsheet become a table, and on
macOS text copied from a web page or a word processor becomes Org with
its headings, emphasis, links and lists. Paste as Plain Text
(Ctrl+Shift+V) inserts the text as it is. In source blocks, text is always
pasted as it is.

* Views

- Source view (Ctrl+/) :: the Org text itself, with colors, line numbers
  and every character shown.
- Split view (Ctrl+\) :: the source beside the rich view of the same
  document. A click makes a side the active one.
- Outline (Ctrl+Shift+O) :: the headings in a sidebar. A click jumps to a
  heading; dragging one moves its subtree, before the heading it is dropped
  on or, on the lower half, after it.
- Focus mode (F8) :: only the section you are writing in.
- Narrowing :: /Narrow to Subtree/, /Element/ or /Block/ in the command
  palette shows only that part; /Widen/ shows everything again.
- Soft wrap (Alt+Z) :: long lines wrap at the window's edge, or scroll
  sideways.

In the terminal, headings move right by level, and the text under a
heading starts where its title does, as with Emacs's =org-indent-mode=;
=editor.outline_indent = false=, or =#+STARTUP: noindent= in a file, keeps
all text at the left edge.

The text column is 80 characters wide and starts at the left edge of the
window; the setting =editor.line_width= changes its width (0 for the whole
window), and =editor.center_text = true= puts it in the middle, like a
page.

* Finding and commands

Ctrl+F finds, Ctrl+H finds and replaces. Every match is marked; Enter and
Shift+Enter step through them. In the replace field, Enter replaces one
match and Alt+Enter all of them, in one undo step. Alt+R, or the =.*=
button, makes the search a regular expression; the replacement can use
=$1= for its groups.

Ctrl+Shift+P (or F1) opens the command palette: every command that
applies, with its keys. Type part of a name to find it. Commands that need
something, such as a heading level, ask for it. In a terminal the palette
is Ctrl+G, and the status line says so.

* Documents and projects

A window holds several documents. Opening a file (Ctrl+O, the File menu, a
file link, or a file opened from Finder) shows it in the same window. The
open files are listed on the left; the setting =ui.open_files= puts them
at the top as tabs, or hides them, and Ctrl+Shift+E shows or hides the
list. A click shows a document. Ctrl+Tab and Ctrl+PageDown go to the next
one, Ctrl+Shift+Tab and Ctrl+PageUp to the previous one, Ctrl+Alt+O lists
them by name, Ctrl+Alt+R lists the files you opened recently, and Ctrl+W
closes the document (asking first when it has unsaved changes).

A project is a folder in your project list: /Add Project/ adds the
document's folder, /Add Project Folder…/ in the Project menu chooses one,
and a folder under version control (Git, Mercurial, Subversion) or with a
=.projectile= file joins the list by itself when you open one of its files
(=projects.auto_add = false= turns that off). Nothing is written into the
folder: the list is kept in =projects.toml= in the settings folder,
=~/.config/kalem/projects.toml= unless =KALEM_CONFIG_DIR= or
=XDG_CONFIG_HOME= says otherwise (=%APPDATA%\kalem= on Windows).

The document you are in decides the current project: Ctrl+P and Search in
Project work on its project at once, and Switch Project lists it first.
Files of a project are listed under its name; files outside every project
come after, one by one. The status bar shows the project of the
document.

| Keys         | Command                                              |
|--------------+------------------------------------------------------|
| Ctrl+Alt+P   | Switch Project: its last file, or its files          |
| Ctrl+P       | Find File in Project, recent files first             |
| Ctrl+Shift+F | Search in Project; Alt+C case, Alt+W words, Alt+R regular expression |
|              | Recent Files in Project, Remove Project, Rename Project (palette)    |

The file list follows the ignore rules of ripgrep: =.gitignore= and
=.ignore= files, with or without a Git repository, and never =.git= itself
or binary files. The list of projects and recent files is kept in
=projects.toml=, beside =settings.toml=.

* Citations

/Insert Citation/ (Insert menu, or the palette) lists the entries of the
files =#+BIBLIOGRAPHY:= names (BibTeX, BibLaTeX or CSL-JSON, beside the
document or anywhere); typing narrows the list by key, author and title,
and Enter writes =[cite:@key]=, or adds =; @key= when the cursor is in a
citation already. With the cursor on a citation's key, the status bar
shows the entry it cites, or that no bibliography has it; in the
graphical editor, so does a tooltip under the mouse.

* Exporting

/Export as HTML/, /Export as Markdown/, /Export as LaTeX/ and /Export as
Plain Text/ (Export…,
Ctrl+Alt+E, the File menu, or the palette) write the document beside its file, or where =#+EXPORT_FILE_NAME= says,
with unsaved changes too. The result is what Emacs's Org exporter writes:
=#+OPTIONS=, =#+INCLUDE=, macros, footnotes, tables, links and source
blocks behave as there. Kalem does not run code: source blocks show their
code and the results already in the file.

The LaTeX file is Emacs's too: =#+LATEX_CLASS= (=article=, =report= or
=book=), =#+LATEX_CLASS_OPTIONS=, =#+LATEX_HEADER= and =#+ATTR_LATEX= on
tables, figures, lists and blocks work as in Org's manual. A Kalem
document's fonts, sizes, colors, highlights, alignment and spacing go into
it too (fonts only for XeLaTeX and LuaLaTeX, =#+LATEX_COMPILER=).

/Export as PDF (LaTeX)/ writes the LaTeX file and compiles it in the
background with =latexmk=, else the TeX engine (=pdflatex=, or the one
=#+LATEX_COMPILER= names) or =tectonic=, whichever is installed; TeX Live,
MacTeX or MiKTeX provide them. When LaTeX stops on an error, the status
line gives it at the line of the Org file it comes from. With
=export.open_after= on, the PDF opens when it is ready.

With pandoc installed (https://pandoc.org), /Export as Word/,
/OpenDocument/, /EPUB/ and /RTF/ write those formats, and /Import as Org/
(File menu) turns a Word, OpenDocument, Markdown, HTML, EPUB or RTF file
into an Org file beside it, its pictures in a =NAME_assets= folder. The
import is cleaned up: the anchors and =CUSTOM_ID= properties pandoc adds
and nothing links to go, and tables are aligned. Kalem's own formatting
(fonts, colors) does not reach Word or OpenDocument yet.

Citations (=[cite:@key]=, =[cite/t:@key]=, =[cite/a/c:@key]= and the
other styles and variants of Org's manual) come out as Org's =basic=
processor writes them: "(Author, Year)", "Author (Year)", numbers, or a
footnote for the =note= and =ft= styles, with the keys looked up in the
files =#+BIBLIOGRAPHY:= names (BibTeX, BibLaTeX or CSL-JSON).
=#+PRINT_BIBLIOGRAPHY:= becomes the list of the works cited, sorted by
author; =#+CITE_EXPORT: basic numeric= (or =plain=) chooses its style, and
a third word the default citation style.

=#+CITE_EXPORT: csl apa= renders citations and the bibliography in a
Citation Style Language style instead: the name of one of the styles
Kalem ships (=apa=, =ieee=, =mla=, =chicago-author-date= (the default),
=chicago-notes=, =nature=, =vancouver= and about eighty more), or a =.csl=
file beside the document. Author–date and numeric styles put the
citation in the text, note styles in a footnote; =[cite:see @key p. 12]=
passes "p. 12" as the locator. HTML gets a =csl-bib-body= list, LaTeX a
=cslbibliography= environment with its definitions in the preamble, as
Org's =csl= processor writes them. =#+LANGUAGE= chooses the style's
terms.

For LaTeX, =#+CITE_EXPORT: biblatex= and =#+CITE_EXPORT: natbib= leave
citations to those packages, as Org does: =[cite/t:@key]= becomes
=\textcite{key}= or =\citet{key}=, =#+PRINT_BIBLIOGRAPHY:= becomes
=\printbibliography= (its =:key value= options passed on) or
=\bibliography=, and the package and the bibliography files go into the
preamble. The second word is the style (=biblatex authoryear=, =natbib
plainnat=). /Export as PDF/ then runs =biber= or =bibtex= between LaTeX
runs, as =latexmk= does.

Plain text is filled to 72 columns as Emacs fills it, with underlined
titles, boxed code and tables drawn in ASCII; =export.text_charset =
"utf-8"= uses UTF-8 lines, bullets and quotes instead.

From the command line:

#+begin_src sh
kalem export notes.org                  # notes.html
kalem export notes.org --to md -o -     # Markdown to standard output
kalem export *.org --body-only          # only the body of each page
kalem export paper.org --to latex       # paper.tex
kalem export notes.org --to txt         # plain text, 72 columns (utf8 for UTF-8)
kalem export paper.org --to pdf         # paper.pdf; errors as paper.org:LINE: …
kalem export report.org --to docx       # also odt, epub, rtf (pandoc)
kalem import report.docx                # report.org, cleaned up (pandoc)
kalem export paper.org --to latex --source-lines   # %% org:LINE comments
#+end_src

* The file manager

Kalem has a file manager like Emacs's Dired. Ctrl+Alt+D lists the folder of
the document, the cursor on its file; the same key goes back to the
document. The toolbar's /File Manager/ and /Projects/ buttons, the two
entries at the bottom of the list of open files, the key shown at the
right of the terminal's status line (a click works too), the File and
Project menus and the palette (type =files=, =projects= or =dired=) all get
there. Opening a folder (Ctrl+O, =kalem FOLDER=, =:e FOLDER=) lists it too.
A window has one file manager, which goes from folder to folder; the list
of open files calls it /File Manager/.

It has two views. The normal view lists a folder: permissions, size,
modification time and name, folders first. The projects view
(Ctrl+Alt+Shift+D, or /Projects/ in the Project menu) lists every project,
and only the projects, as if they were all in one folder. Opening a project
lists its folder; going up from there shows the projects again. =P=
switches between the two views.

The listing is read-only text: the arrow keys, search, and with Vim keys
=j k gg G= and =/= work as in any document. A click on a name opens it.
Commands act on the marked entries, or on the one at the cursor.

| Keys                   | Command                                          |
|------------------------+--------------------------------------------------|
| Enter, click           | Open: a folder is listed, a file opens           |
| =^=, =-=, Backspace    | Parent folder (from a project's folder: the projects) |
| =n=, =p=               | Next, previous line                              |
| =P=                    | Projects view, and back                          |
| =g=                    | Read the folder again                            |
| =(=, =.=               | Details; dot files                               |
| =s=                    | Sort by name, time, size, extension              |
| =F=                    | Filter by name                                   |
| =m=, =u=, =U=, =t=     | Mark, unmark, unmark all, toggle marks           |
| =d=, =x=               | Flag for deletion; move the flagged to the trash |
| =% m=, =* /=, =* .=    | Mark by regular expression, folders, extension   |
| =c=                    | New file (a name ending with =/= makes a folder) |
| =+=                    | New folder                                       |
| =R=, F2                | Rename or move                                   |
| =C=                    | Copy                                             |
| =D=, Delete            | Move to the trash (asks first)                   |
| =S=, =M=, =T=          | Symbolic link, permissions, touch                |
| =w=                    | Copy the names                                   |
| =q=                    | Close the file manager                           |

/Delete for Good/, /Copy Paths/, /Reverse Order/ and /Stop File
Operations/ are in the palette. Copying and moving run in the background,
with their progress in the status bar. When a file is already at the
destination, Kalem asks: overwrite, skip, or keep both (the new one becomes
=name (2).ext=), for that file or for all that are left.

With Vim keys the file manager's keys come first, except =n=, =p=, =w= and
Backspace, which Vim keeps; =g r= reads the folder again, =g g= goes to the
first entry and =Y= copies names. From a document, =-= opens the file
manager (as vim-vinegar and Doom do; in the file manager it goes up), and
so do =:Ex=, =:Explore= and =:E=; =:Projects= shows the projects. =SPC o -=
opens the file manager and comes back, =SPC o P= shows the projects and
=SPC p D= the project's folder.

* Keys

Kalem has two keymaps, chosen in the settings: Word-like keys, the
default, and Vim keys. On macOS, Command takes the place of Control in the
Word-like keys (Cmd+S saves).

** Word-like keys

| Keys                   | Command                        |
|------------------------+--------------------------------|
| Ctrl+S, Ctrl+Shift+S   | Save, Save As                  |
| Ctrl+Z, Ctrl+Y         | Undo, Redo (also Ctrl+Shift+Z) |
| Ctrl+X, Ctrl+C, Ctrl+V | Cut, Copy, Paste               |
| Ctrl+A                 | Select All                     |
| Shift+Enter            | Line break within a paragraph  |
| Ctrl+,                 | Settings                       |
| Ctrl+Q                 | Quit                           |
| Ctrl+O, Ctrl+N, Ctrl+W | Open, New, Close document      |
| Ctrl+Shift+P, F1       | Command palette (Ctrl+G in terminals) |

The other keys are in the sections above, and in the command palette.

** Vim keys

With =editor.keymap_profile = "vim"=, the editor has Vim's modes. Normal
mode moves and edits: =h j k l=, =w b e=, =0 ^ $=, =gg G=, =f t ; ,=, =%=,
={ }=, counts, the operators =d c y > <= and =gu gU g~= with motions and
text objects (=iw=, =i"=, =i(=, =ip= and their =a= forms; in Org
documents also =ih= the headline's title, =iR= the subtree below its
headline, =ii= a list item's text, =ic= a table cell and =ie= the inside
of emphasis, and their =a= forms with the whole headline, subtree, item,
cell or emphasis), =x D C p P J r ~ u= Ctrl+R and =.= to repeat. =v= and =V= select characters and lines, Ctrl+V a block of columns
(=I= and =A= then type on each of its lines).
=/= and =?= search, =n N * #= repeat. Registers: ="a= to ="z=, and ="+=
for the system clipboard. The command line knows =:w=, =:q=, =:q!=,
=:wq=, =:x=, =:NUMBER=, =:noh=, =:e FILE=, =:bn=, =:bp=, =:bd= and =:ls=;
=gt= and =gT= go to the next and previous document.

Space is the leader, as in Doom Emacs. Press it and a panel shows what can
follow:

|-----------------------+------------------------------------------|
| =SPC p p=             | Switch Project                           |
| =SPC p f=, =SPC SPC=  | Find File in Project                     |

=editor.vim.leader= makes another key the leader (="\\"= or =","=, say).

Insert mode (=i a o= and the others) types as usual, with the Word-like
keys. Keys with Control or Alt that Vim does not use, such as Ctrl+S, keep
their Word-like meaning in every mode. In Org documents, =>>= and =<<=
demote and promote headings and indent list items.

=editor.vim.modes= limits Vim keys to some kinds of documents, for example
=["plain"]= for plain text only.

** Your own keys

Every key can be changed. =keymap.json= in the settings directory changes
keys:

#+begin_src json
[
  // Ctrl+Shift+W sets the tag "work".
  { "keys": "ctrl+shift+w", "command": "org.tags.set",
    "args": { "tags": ["work"] }, "when": "onHeadline" },
  // No Ctrl+B for bold.
  { "keys": "ctrl+b", "command": "-org.emphasis.bold" },
  // Two-key sequences, Emacs style.
  { "keys": "C-c C-t", "command": "org.todo.cycle" },
  // Vim keys: SPC p t lists the project's recent files; no SPC q q.
  { "keys": "leader p t", "command": "project.recentFiles", "when": "vimCommand" },
  { "keys": "leader q q", "command": "-app.quit" }
]
#+end_src

Command IDs are shown in the palette. =leader= stands for the Vim leader.
=docs/keymaps/emacs.json= is a complete keymap with Emacs Org mode keys,
to copy into =keymap.json=.

In a terminal, keys with Alt reach Kalem only when the terminal sends
them: in macOS Terminal and iTerm2, set Option to act as Meta (Terminal:
Settings, Profiles, Keyboard, "Use Option as Meta key"; iTerm2: Profiles,
Keys, "Left Option key: Esc+"). Terminals with the kitty keyboard protocol
(kitty, WezTerm, Ghostty, foot) send every key as it is.

* Other files

Kalem opens any text file. Org files get the rich editor. Other files are
edited as plain text: monospace, colored by their language, with line
numbers, the cursor's line marked and indentation guides. Tab follows the
file's indentation (tabs, or its number of spaces) and indents selected
lines; Shift+Tab outdents.

The kind of a file comes from, in order: your choice with the command
/Set Document Mode/ (remembered in the workspace settings), a mode line
such as =-*- mode: org -*-= on the first line, the extension, and a
=#!= line. Markdown and CSV files are edited as text for now. Binary
files are not opened.

* Settings

Choose /Settings/ in the Kalem menu (Ctrl+, or Cmd+,) for the theme, the
keys, the language, the text size and the font. Changes apply to every
window and are saved in =settings.toml=, in the settings directory:
=$KALEM_CONFIG_DIR=, or =kalem= in =$XDG_CONFIG_HOME=, =%APPDATA%= on
Windows, or =~/.config=. A project can have its own
=.kalem/settings.toml=, which applies over yours.

** Themes

Light and dark themes follow the system unless =editor.theme= says
otherwise; the terminal editor asks the terminal for its background. To
change colors, copy =crates/kalem-core/themes/light.toml= or =dark.toml=
to =themes/= in the settings directory and edit it; colors you leave out
keep their values.

* Files

Saving is atomic: a crash never leaves half a file. Line endings, a byte
order mark, file permissions and symbolic links are kept. When another
program changes an open file, Kalem reloads it if you have no unsaved
changes; otherwise the status bar says so, and /Revert to Saved/ takes the
other version. Undo goes back past a reload.

* The command line

| Command                     | What it does                                                               |
|-----------------------------+----------------------------------------------------------------------------|
| =kalem check FILE...=       | Syntax diagnostics; exits 1 on errors (=--deny-warnings=, =--format json=) |
| =kalem fmt FILE...=         | Aligns tables and tags, tidies blank lines; =--check= for CI               |
| =kalem query FILE... MATCH= | Headlines matching an Org match string, such as ='TODO="NEXT"+work'=       |
| =kalem parse FILE=          | The syntax tree                                                            |
| =kalem dump FILE=           | The syntax tree as JSON, in Emacs's terms                                  |
| =kalem diff-emacs FILE...=  | Compares the parse with Emacs (development)                                |

=--format json= gives stable output for scripts.

* When something goes wrong

The log is =kalem.log= in the state directory: =$KALEM_STATE_DIR=, or
=kalem= in =$XDG_STATE_HOME=, =%LOCALAPPDATA%= on Windows, or
=~/.local/state=. After a crash, a report is in the same directory. Please
attach both to a bug report, with =kalem tui --detect= for problems in the
terminal.
